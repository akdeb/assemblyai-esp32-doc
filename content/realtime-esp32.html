    Realtime speech on ESP32

    Build a talking ESP32-S3 device with Elato, the open-source voice AI stack, powered by AssemblyAI streaming Speech-to-Text, LLM Gateway, and Text to Speech.

    ​
    Overview

    An ESP32-S3 can't run a speech model, so it doesn't try. The board streams microphone audio to a small Deno edge server and plays back whatever audio comes back. The server does the rest: it feeds your speech to AssemblyAI streaming Speech-to-Text, waits for the end of your turn, asks LLM Gateway for a reply, and speaks it with Text to Speech. Talk over the agent, or press the button, and playback stops immediately. The design comes from Elato, an open-source stack for building talking ESP32 devices, created by Akash Deb. The full Elato project ships ESP32 firmware, a Deno edge server, a Next.js app and Supabase, and works with 100+ voice models. The code on this page is a minimal version of it with AssemblyAI as the speech provider, small enough to read in one sitting.
    Set ASSEMBLYAI_API_KEY on the edge server only. The key never touches the device. Get one from the AssemblyAI dashboard.

    Build the voice agent

    ​
    Step 1: Set your API key and device token

    The device token is a shared secret between the ESP32 and your edge server. 
    export ASSEMBLYAI_API_KEY=<your-key>
export DEVICE_TOKEN=$(openssl rand -hex 16)

    ​
    Step 2: Run the edge server

    The server is one Deno file, examples/esp32-realtime/server/main.ts. Run it locally, or deploy it to a Deno-compatible host close to your users. 
    deno run -A examples/esp32-realtime/server/main.ts
    It talks to three AssemblyAI endpoints. Every one authenticates with your API key. 
    const STT_URL =
  "wss://streaming.assemblyai.com/v3/ws?" +
  new URLSearchParams({ speech_model: "universal-3-6-pro", sample_rate: String(MIC_RATE) });

const TTS_URL =
  "wss://tts.us.assemblyai.com/v1/ws?" +
  new URLSearchParams({
    voice_id: VOICE_ID,
    language: "english",
    sample_rate: String(SPK_RATE),
    encoding: "pcm_s16le",
  });

const LLM_URL = "https://llm-gateway.assemblyai.com/v1/chat/completions";
    STT stays open for the whole session. When a final turn arrives, the server forwards the transcript to the device and, if the agent is mid-reply, cuts it off first. 
      const stt = authedSocket(STT_URL);
  stt.binaryType = "arraybuffer";
  stt.onmessage = (ev) => {
    const msg = JSON.parse(ev.data as string);
    if (msg.type !== "Turn") return;
    if (speaking && msg.transcript?.trim()) interrupt(); // barge-in
    if (msg.end_of_turn && msg.transcript?.trim()) {
      send({ type: "transcript", role: "user", text: msg.transcript });
      turns.push(msg.transcript);
      void drain();
    }
  };
    Replies are handled one at a time: ask the LLM, then speak the answer. 
      async function drain() {
    if (working) return;
    working = true;
    try {
      while (turns.length) {
        history.push({ role: "user", content: turns.shift()! });
        send({ type: "state", state: "thinking" });
        const answer = await think(history);
        history.push({ role: "assistant", content: answer });
        send({ type: "transcript", role: "assistant", text: answer });
        await speak(answer);
        send({ type: "state", state: "listening" });
      }
    } catch (err) {
      console.error(err);
      send({ type: "error", message: String(err) });
    } finally {
      working = false;
    }
  }

    ​
    Step 3: Flash the firmware

    Open examples/esp32-realtime/firmware in PlatformIO. In Config.h, set your Wi-Fi credentials, the edge server host, and the same DEVICE_TOKEN. Then flash: 
    cd examples/esp32-realtime/firmware
pio run -t upload && pio device monitor
    The firmware has two jobs. One task reads the mic and streams PCM16 to the server. The main loop drains a playback buffer into the speaker, and clears it on interrupt. 
    // Core 0: read the mic, convert 32-bit I2S samples to PCM16, stream to the server.
static void micTask(void*) {
  static int32_t raw[MIC_FRAME];
  static int16_t pcm[MIC_FRAME];
  for (;;) {
    size_t got = 0;
    i2s_read(MIC_PORT, raw, sizeof(raw), &got, portMAX_DELAY);
    size_t n = got / 4;
    for (size_t i = 0; i < n; i++) pcm[i] = (int16_t)(raw[i] >> 14);  // 32 -> 16 bit with gain
    if (connected) ws.sendBIN((uint8_t*)pcm, n * 2);
  }
}

// Core 1 loop pushes ring buffer data to the speaker.
static void pumpSpeaker() {
  static uint8_t chunk[1024];
  size_t n = min(ringUsed(), sizeof(chunk));
  if (!n) return;
  for (size_t i = 0; i < n; i++) { chunk[i] = ring[tail]; tail = (tail + 1) % RING_BYTES; }
  size_t written = 0;
  i2s_write(SPK_PORT, chunk, n, &written, 0);
}

    ​
    Step 4: Talk to it

    When the serial monitor prints server connected, start talking. Transcripts show up in the monitor and the reply plays through the speaker. Press the button, or talk over it, to interrupt.

    ​
    How it works

    • Always listening. The STT socket stays open for the whole session. AssemblyAI's turn detection decides when the user is done (end_of_turn), so there's no push-to-talk.
    • One reply at a time. Final turns are queued. For each one the server calls LLM Gateway with the running history, then opens a TTS socket for the answer.
    • Barge-in. If speech arrives while the agent is talking, or the button is pressed, the server sends Cancel to TTS and an interrupt to the device, which clears its playback buffer.
    • Raw PCM. The example sends uncompressed PCM16, about 32 KB/s up and 48 KB/s down. That's fine on Wi-Fi. Elato's firmware compresses audio with Opus, and adding it here is the main upgrade if your network is weak.

    ​
    Limitations and troubleshooting

    Akash Deb, founder of Elato, has run this design on real devices and documents where it falls short:
    • Cold starts. Connecting to a freshly started edge server takes about 2 to 3 seconds.
    • Response time. Elato reports roughly two to three seconds end to end across its global stack. That covers Wi-Fi, network distance, model time and playback, so measure on your own hardware and region.
    • Session length. Edge hosts end a connection when their wall-clock limit is reached. Elato has tested up to 17 minutes of uninterrupted conversation.
    • Interruptions. The ESP32 doesn't detect speech itself. It stops playing only when the server sends interrupt or you press the button.
    Two more limits are specific to this example. It sends raw PCM, so it needs a steady Wi-Fi link. And DEVICE_TOKEN is one shared secret for every device, which is fine for a prototype. Give each device its own credentials before you ship, as Elato does with its Supabase device registration. If something doesn't work, isolate one half at a time:
    • Speaker is silent. Before you debug the voice pipeline, get a small internet-radio sketch playing through the MAX98357A on its own. If the radio plays, your wiring and I2S pins are fine and the problem is in the audio stream. If it doesn't, recheck the pins in Config.h.
    • Mic isn't working. Try a local LAN server first. Run the edge server on your computer, join the same Wi-Fi, and in main.cpp replace ws.beginSSL(RELAY_HOST, RELAY_PORT, ...) with ws.begin(<your computer's IP>, 8000, ...). Once your transcripts show up in the serial monitor, move to a hosted server.
    • Stuck connecting. Power-cycle the board after you change Wi-Fi credentials, and check that DEVICE_TOKEN matches on the device and the server.

    Voice Agent API alternative

    Instead of chaining three APIs, the edge server can open one WebSocket to the managed Voice Agent API and let AssemblyAI run the whole loop. Elato supports both, so you can choose per character.
    STT + LLM Gateway + TTS (this example)Voice Agent API
    ConnectionsThree: STT socket, LLM Gateway request, TTS socketOne: wss://agents.assemblyai.com/v1/ws
    ModelsYou choose: universal-3-6-pro, an LLM Gateway model, a TTS voiceManaged by AssemblyAI. You choose the voice and, optionally, a transcription mode.
    Turn-takingThe server reacts to end_of_turn, then calls the LLM and TTSHandled by AssemblyAI (semantic turn detection and barge-in)
    Audio16 kHz PCM16 in, 24 kHz PCM16 out24 kHz PCM in and out. Resample 16 kHz mic audio before sending.
    ToolsYou call tools yourself in the serverDeclare them in session.update, run them in the server, send the results back
    GreetingThe server generates and speaks itThe model composes it from a reply.create instruction
    Ending a callClose the socketsSend session.end so you aren't billed for the reconnect grace window
    You configure the session with one session.update event: system_prompt, input.format, output.voice, output.format, and tools. The voice and output format can't change after the first update. The agent speaks English, Italian, Spanish, German, Portuguese and French. Your API key needs Voice Agent API access, not only streaming transcription. The Voice Agent API doesn't expose its STT, LLM or TTS models, so use the pipeline above if you need to pin or swap one.

    ​
    Customize and extend

    • Change the persona with SYSTEM_PROMPT, the model with LLM_MODEL, and the voice with TTS_VOICE_ID.
    • Add tool calls (timers, smart-home actions) to the LLM Gateway request and run them in the server.
    • Add keyterms for your product names to the STT connection to improve recognition.
    • Use the full Elato project for the Next.js app and Supabase schema that handle device registration, characters, and conversation history.
    • Deploy the server near your users. End-to-end latency is Wi-Fi, network distance, model time, and playback, so measure on your hardware and region.
